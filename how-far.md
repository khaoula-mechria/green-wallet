# How Far Is This Project? — Plain-Language Status Report

This document explains, in simple terms, what is actually in this repository, what
works, what doesn't (or isn't real), how the pieces fit together, and what every single
file does. It's written for someone who wants to understand the project without reading
all the code first.

---

## 1. The one-paragraph summary

This is a working demo (not a finished product) of a website where households can sell
and buy electricity from each other. Some households produce more power than they use
(solar panels, wind) and can sell the extra. Others use more than they produce and need
to buy some. A fake "day" runs automatically in the background (sun goes up, sun goes
down) so production numbers change over time like a real solar panel would. When
someone buys electricity, a digital coin (called TEC) moves from the buyer to the
seller, and that transaction gets permanently recorded on a simple blockchain built
into this app. Everything runs on your own computer — no real money, no real electricity,
no real blockchain network is required to try it, although a real one (Hedera) can be
plugged in if you want.

---

## 2. What works right now (tested and verified)

These things were actually run and checked — not just written and assumed to work:

- **Creating an account / logging in** — works. You pick a household type (producer,
  consumer, or prosumer = both) and get a password-protected account.
- **Submitting an energy reading** — works. You type in how much power you produced and
  consumed; the app calculates whether you have extra (surplus) or a shortage (deficit).
- **Automatic simulation** — works. Every few seconds, all households get a new
  automatic reading following a realistic "sun goes up at 6am, peaks at noon, down by
  6pm" curve, without you doing anything.
- **Auto-conversion of surplus into coins** — works. If you produced more than you used,
  the extra amount is automatically turned into TEC coins in your wallet.
- **Creating a sell offer (marketplace listing)** — works. You can't offer to sell more
  than you actually have banked up.
- **Buying energy from someone's offer** — works. Coins move from buyer to seller, the
  offer's remaining amount goes down, and it's all recorded.
- **Blockchain recording** — works, but it's a **simplified, locally-built blockchain**
  (explained in section 4), not a real public blockchain by default.
- **Preventing cheating** — tested and confirmed:
  - Can't sell more energy than you have.
  - Can't buy with coins you don't have.
  - Can't buy more than an offer has left.
  - Can't accidentally "execute" the same purchase twice (double-spending).
  - Two people can't both buy the last bit of the same offer at the same time.
- **Dashboard, wallet, transaction history, blockchain explorer, microgrid map** — all
  built and confirmed to show live data on-screen (checked with real screenshots in a
  browser, not just "it should work").
- **Automated tests** — 30 automated checks exist and all 30 currently pass. They cover
  the money-and-energy math, the offer/purchase rules, and the blockchain rules.

## 3. What does NOT work / is NOT real

Being direct about the limitations:

- **The blockchain is not a real public blockchain by default.** It's a simplified
  version built from scratch inside this app (chained, tamper-evident blocks with
  hashes) — it demonstrates the *idea* correctly, but it is not decentralized and
  nobody outside this app can verify it independently. Turning on real Hedera
  Hashgraph mode is possible, but requires YOU to create a free account and enter your
  own keys — this was never turned on or tested with real credentials, because no real
  account was ever provided.
- **No real electricity or real meters are involved.** All production/consumption
  numbers are either typed in by hand or generated by the built-in simulator. There is
  no connection to a real solar panel, smart meter, or power grid.
- **No real money.** TEC coins only exist inside this app's own database.
- **The "smart contract" is regular code, not a blockchain smart contract.** The rules
  (can't oversell, can't overspend, etc.) are enforced by the backend server, the same
  way a normal website enforces rules — not by code running on a blockchain that nobody
  can secretly change.
- **Docker was written but never fully test-run in this environment**, because Docker's
  background engine wasn't switched on when this was built. The configuration file was
  checked for syntax errors (that passed), but nobody has actually watched
  `docker compose up` finish successfully end-to-end. Running it locally without Docker
  *was* fully tested and works.
- **No real login security hardening.** Login uses a standard method (JWT), fine for a
  demo, but the default secret keys in the example settings file are placeholders —
  they must be changed before anyone would consider this "production-ready."
- **No email, phone verification, or password reset.** If you forget your password
  there is no recovery flow.
- **Not mobile-app tested.** Only tested as a website in a desktop browser window.

## 4. Architecture — how the pieces talk to each other

Think of it as four layers, stacked:

```
 [ Browser / Website ]                 <- what you see and click
        |  (talks over the internet using simple web requests)
 [ Backend Server ]                    <- the "brain": checks rules, does the math
        |
        |-- [ Database file ]         <- remembers households, offers, trades, coins
        |
        |-- [ Blockchain part ]       <- separately records every coin movement
```

- The **website** (frontend) never trusts itself — it just displays data and sends
  requests. All the real rule-checking happens on the **server** (backend), so a user
  can't cheat by tampering with their own browser.
- The server is split into small specialized pieces (one for households, one for
  offers, one for trades, one for coins, one for the blockchain) instead of one giant
  file — this makes it easier to find and fix things.
- The blockchain part is deliberately kept separate and swappable: the rest of the app
  doesn't care whether it's talking to the simplified built-in blockchain or a real one
  — it just asks "record this transaction" and gets back a confirmation, the same way
  either way.
- The database only stores facts (who owns what, what was offered), never rules — rules
  live in the server code.

### The trading flow, step by step

```
Producer's panel makes power
        -> reading gets submitted (by hand or by the simulator)
        -> app calculates: production - consumption = surplus or deficit
        -> if surplus: coins are automatically created and given to the producer
        -> producer lists some of their surplus for sale (an "offer")
        -> consumer sees the offer, picks how much to buy
        -> app double-checks the offer still has enough left, and the buyer has enough coins
        -> coins move from buyer to seller
        -> transaction is written into the blockchain part
        -> offer is updated (or closed if fully bought)
        -> everyone can see the result in their history / the blockchain explorer page
```

## 6. How to run it

### Easiest way — Docker (one command, if Docker Desktop is running)

```bash
docker compose up --build
```
Then open the website at **http://localhost:8080**. The server runs at
**http://localhost:4000** in the background. The database starts empty, so the app
automatically creates 10 demo households the first time it boots — you don't need to
do anything extra.

> Note: this exact command was written and its configuration file was checked for
> mistakes, but it was not personally watched running to completion in this
> environment because Docker's background engine wasn't turned on at the time. It
> should work, but this is the one thing that hasn't been visually confirmed.

### Manual way — two terminals (fully tested, confirmed working)

**Terminal 1 — start the server:**
```bash
cd backend
npm install
npm run dev
```
Leave this running. It listens on `http://localhost:4000` and creates the demo
households automatically the first time.

**Terminal 2 — start the website:**
```bash
cd frontend
npm install
npm run dev
```
Leave this running too. Open **http://localhost:5173** in your browser.

### Running the automated tests

```bash
cd backend

```
You should see `30 passed`.

### Turning on the real blockchain (optional, advanced, not required)

Only do this if you want real blockchain transactions instead of the built-in
simplified one:

1. Make a free account at `portal.hedera.com`.
2. Put your account ID and private key into `backend/.env` (copy `backend/.env.example`
   first).
3. Run `npm run init:token` once inside `backend/` — this creates the real coin and
   prints an ID.
4. Put that ID into `.env` too, and restart the server.

If you skip all of this (the default), everything still works, just with the built-in
simplified blockchain instead of a real one.
